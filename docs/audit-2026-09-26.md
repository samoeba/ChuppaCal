# ChuppaCal re-audit — September 26, 2026

> Historical audit. The user subsequently approved 5, 7–12 and held 1–4, 6. The approved app work, live Supabase migrations 005–009 and a direct Vercel deployment were subsequently completed, but the deployed app has not passed full household acceptance. Findings below describe the earlier audit state, not the current release. See the [September 27 release gate](release-2026-09-27.md) and [README](../README.md) for current status.

## Outcome and scope

Rechecked the prior audit against the application, actions/routes, components, keyboard, database migrations, configuration, tests, specs and kiosk runbook. Implemented the confirmed low-risk application fixes below. Changes are local and uncommitted; no production deployment, database migration, credential rotation or live-family write was performed.

The application is a capable personal-household prototype. It is **not yet ready to be treated as a secure multi-tenant product**. The biggest remaining work is authorization/data integrity, not adding more features. For household use, first restore/verify the backend, review the security trade-offs and exercise the complete workflows on test data and the actual Pi.

“Confirmed” below means reproducible in source, configuration or tests. It does not mean a live exploit was attempted. The configured Supabase hostname failed a read-only DNS lookup with `ENOTFOUND`, including outside the sandbox. Column/bucket probes therefore remained unverified. A paused/deleted project, stale URL or DNS problem is possible; the cause cannot be determined from this checkout alone.

## Revalidation of the previous findings

| Finding | Verdict and action |
| --- | --- |
| Parental PIN is not secure authorization | **Confirmed, partly mitigated.** `pin_hash` is actually plaintext, downloaded and compared by `components/pin-gate.tsx`; actions do not require a server-issued parent authorization grant. Removed the implicit `0000` fallback and made missing configuration explicit. A real fix needs the authorization/migration decision below. |
| Google OAuth credentials reach the browser | **Confirmed, partly mitigated.** Settings previously selected `calendar_connections.*`; it now requests explicit nonsecret fields and uses `CalendarConnectionSummary`. Google error bodies no longer leak into error messages. The table remains readable under family-wide RLS, so omitting fields in this UI is not a security boundary. |
| Photo privacy/storage policies are too broad | **Confirmed in migrations; live state unverified.** Migration 004 makes the bucket public. Migration 001 only checks authentication and bucket ID for storage upload/read/delete, not the family path. Existing URLs and policies require a coordinated migration. |
| Partner invitations are fragile/insecure | **Confirmed, partly fixed.** The invite now survives login → Google OAuth → callback → onboarding. Joining no longer asks for a new PIN that the server ignores. Requests validate names, color, avatar, PIN and invite shape; existing members cannot create/join another family sequentially. The family UUID remains a reusable invitation granting parent membership; expiry, recipient binding, revocation and concurrent signup safety remain unresolved. |
| Actions trust family/member IDs and reward prices | **Confirmed; action layer hardened.** A verified session now supplies family identity; target records and assignments are checked, inputs validated, reward prices and balances read server-side. Ordinary app calls can no longer set an arbitrary redemption price. Direct Supabase writes and race conditions still require database policies/transactions. |
| Cron reports false success / missing secret opens production route | **Confirmed and fixed.** Missing production secret fails closed; bearer comparison is timing-safe. Per-connection errors return 502 / `ok:false`. The workflow validates JSON as well as status. Credential, deletion and last-sync write errors are checked. |
| Calendar importing is incomplete | **Confirmed and improved.** Google event/calendar-list pagination, repeated-token detection and request timeouts added. Full rolling-window reads prevent unchanged events entering the next 60 days from being missed by `updatedMin`-only imports. Incremental reads remain for deletion detection. Full reconciliation of recurring-series deletions and events moved outside the window remains a separate design. |
| Events overlap, multi-day events disappear, month/date math is brittle | **Confirmed and fixed within the existing time model.** Column packing makes overlapping events reachable. Multi-day entries appear on every overlapping date, with exclusive all-day end dates. Date strings are validated, month shifts clamp correctly, and day grouping uses calendar boundaries rather than fixed 24-hour offsets. The five-day time grid links to day view for events outside its displayed hours. |
| No family timezone; server/device dates can disagree | **Confirmed, still open.** Civil all-day dates and DST grouping are improved, but server-local/browser-local “today,” meals/chores day boundaries and imported timed events do not share an explicit family timezone. A complete fix needs an IANA timezone choice and date-only semantics throughout. |
| Meals/lists remain stale after navigation or refresh | **Confirmed and fixed.** Server snapshots now replace stale local state; meals normalize week URLs and remount editors on week changes. Shared idle refresh runs every minute and on return/online, deferring during editing, dialogs, pending saves and recent interaction. This is polling, not Realtime. |
| Lists can disappear after failed optimistic writes | **Confirmed and fixed.** Delete and clear-completed restore items on failure; new-item success is merged without duplication; temporary items cannot be edited/deleted before persistence. Defaults are no longer written during server rendering: empty boards offer an explicit starter-list action. |
| Long histories can silently truncate totals/data | **Confirmed and fixed for balances and main list/calendar/chore reads.** Added paginated, deterministically ordered reads beyond Supabase’s default 1,000-row response cap. Query failures now surface instead of looking like empty successful pages. For long-term growth, database aggregates should replace sending all history to the client. |
| Hidden actions, modal keyboard issues, small touch targets and silent failures | **Confirmed; incremental fixes implemented.** Visible list-delete and tap-to-undo job controls; shared dialog focus/Escape/scroll-lock/focus-return behavior; labels/selected states; larger key touch targets; reduced-motion support; inline mutation errors and retry/loading states. Settings/member/reward and photo errors are surfaced. A full contrast/screen-reader/Pi acceptance audit remains necessary. |
| Small screens are squeezed | **Confirmed and improved.** Chore columns stack, calendar controls wrap, week/meal grids retain a readable minimum width with explicit horizontal-scroll guidance, list columns fit a phone viewport, and dialogs are viewport bounded. A purpose-built phone agenda/meal-list redesign is a separate product choice. |
| Dependencies, lint and verification are weak | **Confirmed and fixed.** Updated Next.js and matching ESLint config to 16.3.6; applied compatible dependency fixes. Strict lint, TypeScript, regression tests and CI added/expanded. Font files are bundled locally, eliminating build-time Google font downloads. `.npmrc` remains because the installed virtual-keyboard package declares React 16–18 peers; real React 19/device compatibility still merits acceptance testing. |
| Broken chore-generation cron / stale setup docs | **Confirmed and fixed.** Removed the schedule for the nonexistent route. README now documents the actual system, environment, checks and launch cautions. Added `.env.example` and a read-only schema probe; corrected stale architecture notes and removed account email addresses from public operational notes. |
| Missing Pi kiosk auto-launch | **Not a current issue.** The runbook already documents implemented and verified labwc/Chromium auto-launch and recovery. Screensaver and scheduled sleep are separate unfinished features. |
| Realtime is promised as an implemented feature | **Overstated.** Supabase supports it, but the newer project plans explicitly defer subscriptions. The absence of automatic freshness was real; idle polling now provides it without introducing subscription/publication changes. |
| Avatar `<img>` automatically means excessive image cost | **Overstated.** Uploads already crop/resize to a maximum 512px JPEG. Kept that pipeline, added dimensions/lazy loading/decoding/referrer controls and a targeted lint rationale. Public storage remains the actual privacy issue. |
| Five-day “week,” read-only calendar, persistent one-off jobs are bugs | **Not automatically.** These reflect the current specs. A “one-off” label does not currently auto-archive the job; changing this affects household rules and needs a decision. |
| All exposed-looking strings require credential rotation | **Not established.** Public project IDs/account identifiers and placeholders are not proof of a leaked secret. No credentials were rotated. Actual secret exposure, if discovered in history or provider logs, requires coordinated rotation and verification. |

## Additional low-risk work completed

- Scoped public proxy exceptions to exact paths and constrained auth return paths to local paths.
- Calendar connection creation/assignment checks member ownership; callback state is read through the cookie API and cleared on completion/failure.
- Basic response headers: frame denial, content-type sniffing protection and strict referrer policy. A complete CSP needs testing against OAuth, images and deployment requirements.
- Kiosk/filter state is hydration-safe and still functions when localStorage is unavailable; normal devices retain text selection.
- Weather and Google calls have bounded request timeouts.
- Reward deletion now warns about the existing cascade/history consequence rather than presenting it as harmless deletion. The cascade itself is unchanged.
- The UI/UX review skill informed the focus, touch-target and error-recovery pass. Its generic palette/font recommendations were not applied over the existing product identity.

- Browser smoke check of the built login page at 375×812 and 1440×900: layout fits, keyboard focus is visible, and the browser reported no console warnings/errors. No Google sign-in was initiated. Authenticated layouts are covered by component regressions, not claimed as live browser acceptance.

Google pagination/deletion behavior was checked against the official [events.list reference](https://developers.google.com/workspace/calendar/api/v3/reference/events/list) and [incremental sync guide](https://developers.google.com/workspace/calendar/api/guides/sync). The bounded-window importer intentionally does not mix a sync token with incompatible time filters.

## Practical next steps to start using it

1. **Recover and verify configuration.** Confirm the intended Supabase project is active and its URL/keys match both local and hosting configuration. Run the read-only probe, then inspect migration 005 constraints/indexes and policies in the dashboard. Do not assume the production host shares the broken local configuration.
2. **Choose the trust model and authorize the P0 work.** Recommended: parent-only management with a restricted kiosk session, server-side unlock and private credentials/photos. Decide the household timezone and historical star rules at the same time.
3. **Prepare a test environment and restorable backup.** Apply approved forward migrations there first. Exercise cross-family reads/writes and concurrent claims/redemptions, not just the normal UI.
4. **Run end-to-end acceptance.** Sign in/create/join; connect and reconnect a Google test calendar; create/move/cancel recurring and multi-day events; complete/undo expectations; race two job claims; redeem a reward; edit meals across weeks; add/check/edit/delete lists; refresh from another device; test loss of network and visible recovery. Verify data survives reloads.
5. **Deploy this code and approved schema changes in a coordinated release.** Verify the cron secret and scheduler body checks, successful Google imports, current event display, environment redirects and backup/rollback procedure. This audit did not push or deploy.
6. **Run the household pilot on the Pi and one phone.** Confirm touch accuracy, modal keyboard, scroll behavior, reconnect after Wi-Fi loss, midnight rollover, reboot/login persistence and recovery hotkeys using the existing kiosk runbook. Record usability problems before adding optional features.

The highest-value new feature after reliability is a simple “Today” view combining the next events, dinner and remaining expectations. Next would be a parent-approved meal-to-grocery flow. Sleep/screensaver is a sensible hardware follow-up. Voice/AI is last: it broadens the trust and failure surface before the core workflows are fully exercised.
